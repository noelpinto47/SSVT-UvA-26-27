Design and Test Report - Exercise 8: Sub-formulae (sub, nsub)

Time Spent: 12hrs

1. APPROACH

sub :: Form -> Set Form is a recursive structural definition: the sub-formulae of f are always f itself, unioned with sub applied to every immediate child. Built on Set from SetOrd, combined via unionSet. Cnj/Dsj fold unionSet over the full list of children (foldl unionSet (Set [f]) (map sub fs)).

nsub :: Form -> Int cannot be 1 + sum (map nsub children), since that overcounts whenever a subformula repeats structurally under different branches (e.g. Cnj [Prop 1, Prop 1] has exactly 2 distinct subformulae, not 3).
Instead nsub does a stateful traversal (go) carrying a Set Form of formulas already counted, and only counts a node the first time it's seen, mirroring exactly how sub/unionSet dedupe. inSet/insertSet are used rather than a custom elem-based membership check because sets built via unionSet/insertSet stay sorted (both use compare on insert), and inSet relies on that sortedness for its early-exit takeWhile (<= x).

Domain: arbitrary Form values generated by a custom formGen :: Gen Form, sized and using frequency to control branching probability, with Cnj/Dsj arity capped at choose (0, 3) so generated formulas stay small enough for QuickCheck to terminate quickly. A structural shrinkForm :: Form -> [Form] (dropping to immediate children, or shrinking Cnj/Dsj lists) was added so a failing property reports a minimal counterexample instead of an arbitrary large formula; both are wired together as forAllForm = forAllShrink formGen shrinkForm.

2. PROPERTIES

a. Every formula is a sub-formula of itself i.e sub f always contains f
prop_subContainsItself

b. sub f should contain exactly the formulas that are structurally sub-formulae of f i.e inSet g (sub f) == isSubFormula g f
prop_subCorrect

c.  nsub must equal the number of elements in sub i.e nsub f == setSize (sub f) 
prop_nsubMatchesSub

d. There is always at least one sub-formula: the formula itself i.e nsub f >= 1
prop_nsubPositive

Additionally a property which cross-checks nsub against subList which is an independent definition of sub-formulae. i.e nsub f == length (nub (subList f))
prop_nsubMatchesIndependentCount

Note: isSubFormula is a second, independent definition of "is a subformula of" written directly from the informal definition rather than reusing any of sub's logic. subList is a second, independent implementation of subformula-listing for nsub, built without touching SetOrd at all, it is added because prop_nsubMatchesSub alone checks nsub against sub, and both share SetOrd's dedup machinery (unionSet/insertSet/inSet); a bug in that shared machinery could make both sides agree while both were wrong. subList closes that gap.

3. ANSWERS TO GIVEN QUESTIONS

Q1: How can you prove that sub is correct?
Answer: You cannot prove it with QuickCheck, you can only evidence correctness empirically. The approach from HaskellRoad 7.7 is to test against an independent specification.

Two properties are used:

Property 1: Self-containment (structural invariant)
prop_subContainsItself :: Property
prop_subContainsItself = forAllForm $ \f -> inSet f (sub f)
By definition, every formula is a sub-formula of itself. This is the simplest invariant and must hold unconditionally.

Property 2: Agreement with an independent spec
prop_subCorrect :: Property
prop_subCorrect =
    forAllForm $ \f ->
        let Set xs = sub f
        in forAll (oneof [formGen, elements xs]) $ \g ->
            classify (isSubFormula g f) "positive case" $
                inSet g (sub f) == isSubFormula g f

isSubFormula is written directly from the informal definition, without touching SetOrd or sub's logic at all. If sub and isSubFormula agree on every generated (f, g) pair, that is strong evidence sub is correct and this is exactly the "test against an independent spec" strategy from 7.7.


Q2: nsub — recursive implementation and QuickCheck properties
Answer:  nsub carries a Set Form of already-seen formulas through a stateful traversal, counting each node only the first time it appears to be mirroring exactly how sub deduplicates via unionSet:

nsub :: Form -> Int
nsub f = fst (go (Set []) f)
  where
    go seen f
        | inSet f seen = (0, seen)
        | otherwise =
            let seen' = insertSet f seen
            in case f of
                Prop _       -> (1, seen')
                Neg g        -> let (n, s) = go seen' g in (1 + n, s)
                Cnj fs       -> let (n, s) = visitList seen' fs in (1 + n, s)
                Dsj fs       -> let (n, s) = visitList seen' fs in (1 + n, s)
                Impl f1 f2   -> let (n1,s1) = go seen' f1
                                    (n2,s2) = go s1 f2
                                in (1 + n1 + n2, s2)
                Equiv f1 f2  -> let (n1,s1) = go seen' f1
                                    (n2,s2) = go s1 f2
                                in (1 + n1 + n2, s2)
    visitList seen []     = (0, seen)
    visitList seen (f:fs) = let (n1,s1) = go seen f
                                (n2,s2) = visitList s1 fs
                            in (n1 + n2, s2)


QuickCheck properties for nsub:

Property A: ties nsub to sub
prop_nsubMatchesSub :: Property
prop_nsubMatchesSub = forAllForm $ \f -> nsub f == setSize (sub f)
nsub f must equal the number of elements in sub f. Both use SetOrd's dedup machinery, so this checks internal consistency.

Property B: independent ground truth (closes the shared-bug gap):
prop_nsubMatchesIndependentCount :: Property
prop_nsubMatchesIndependentCount = forAllForm $ \f -> nsub f == length (nub (subList f))
subList collects sub-formulae into a plain list (no SetOrd), and nub deduplicates using only Eq. This is fully independent of SetOrd, so a bug shared between sub's unionSet and nsub's insertSet/inSet would still be caught here.

Property C: positivity
prop_nsubPositive :: Property
prop_nsubPositive = forAllForm $ \f -> nsub f >= 1
Every formula is trivially its own sub-formula, so the count is always ≥ 1.

6. ANSWER

Both sub and nsub hold up under all five properties, each passing 500/500 generated Form cases with no counterexamples found:

sub contains f itself on every input, and agrees with the independent isSubFormula definition, including on a genuine 55.4% split of true-positive cases, not just trivial negatives.
nsub agrees with setSize (sub f) (tying it to sub's own count) and with length (nub (subList f)) (a fully independent, SetOrd-free ground truth) so the two checks don't share a possible blind spot.
nsub f >= 1 holds on every generated formula, as expected since every formula is trivially its own subformula.

This is strong empirical evidence both implementations are correct, though as per the limitations below it remains testing, not proof.

7. LIMITATIONS

1. QuickCheck testing gives evidence of correctness, not a proof; it is bounded by what formGen can generate and by maxSuccess (500 here).
2. formGen's frequency weights give Prop a 3/13 chance at every level, biasing generated formulas toward shallow/leaf-heavy trees; deeper, more deeply-nested formulas are under-sampled even at 500 runs.
3. prop_subCorrect's classify split (55.4% positive case) is probabilistic and specific to this run's random seed, a different run could land at a different percentage, though it should stay well above the near-0% a fully independent g would produce.
4. nsub's two checks (prop_nsubMatchesSub, prop_nsubMatchesIndependentCount) both assume Form's derived Eq/Ord instances correctly identify structurally-equal subformulae; a bug there would not be caught by either property.
