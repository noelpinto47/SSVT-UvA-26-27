Design report

    Definitions:
    A permutation is a rearrangement of the elements of a list - so all elements of the input list are present in the permutation.
    A derangement is a permutation for which it is true that for each index of the two lists the elements at that index are not the same.
    Example [1,2,3] and [3,2,1] are derangements but [1,2,3] and [1,3,2] are not.

    Since the two lists xs and ys isDerangement has as input can be any lists we have to first check for 
        1)Are the two lists permutations
        2)Are the two lists derangements

    To check 1 it suffices to check if any one of the lists xs or ys are in the list of permutation(given by permutations function) of the other. 
    Here checking the permutations of any one list is enough because if ys is a permutation of xs then it implies that
    xs would also be a permutation of ys and vice verse.

    To check 2 we have to compare the elements at every corresponding index of xs and ys and ensure they are different for each index in the lists.
    zipWith does this comparision when used with /= and returns a list ex. [T, T, T] when 
    this is the case. This used with all id ensures that the function returns true if and only if all elements are T otherwise it returns false.

    Duplicates
    zipWith also deals correctly with the case that there are duplicates in the list ex [1,2,1] and [2,1,1]
    by focussing on indexes and not the values.

    Edge cases(empty list etc)
    For empty lists [] [] as expected they satisfy both conditions vacously.


Test report

    So to test the permutation aspect we need to test that all elements of the initial list are also in the permutation
    To test that a list ys is a derangement of a list xs we have to test that 
        -ys is a permutation of xs
        -For every index/position in list for xs and ys, the element at that index is different between xs and ys.

    Chosen integer lists    Expected values

    [] and []               → True(vacously)
    [1,2,3] and [2,3,1]     → True(permutation + derangement)
    [1,2,3] and [1,3,2]     → False(permutation but not derangement)
    [1,2,3] and [1,2]       → False(not a permutation)
    [1,2,1] and [2,1,1]     → False(element at index 2 is same(1 in both xs and ys))
    [1,2,3] and [4,5,6]     → False(not a permutation)
    [1,1,2,2] and [2,2,1,1] → True(Derangement despite duplicates)
    [1,2,3] and [4,5]       → False(Not a permutation and but elements at each index different)

    All results were equal to the expected values


    Choice of properties
    1) prop1_LengthIsSame
    This checks if the lengths of the inputs is the same which is a precondition for lists 
    to be permutations of each other. It is inherently weaker than property 2.

    2) prop2_SortsToSameList
    This property essentially checks for permutations singlehandedly as all valid permutations
    sort to the same list.

    3) prop3_AllIndicesDifferentValues
    This property check that the elements at each index of xs and ys are different

    4) prop4_isDerangementSymmetric
    This property checks that flipping the arguments while keeping them the same has no impact on the result

    5) prop5_nonEmptyListCannotBeDerangementOfItself
    This property check that it is universally true that a list cannot be a derangement of itself.
    6) prop6_reversesPreserveDerangement
    This property checks that reversing both the lists has no impact on the result.
    7) prop7_transformPreserveDerangement
    This property checks that transformating each element of the two lists has no impact on the result.

    When put together property 2(2 implies 1) and property 3 cover the conditions needed to test for derangements

    Ordered list of properties(weakest to strongest, then equal in strength, then incomparable)
    1) prop1_LengthIsSame is weaker than prop2_SortsToSameList
    Explanation
    prop2_SortsToSameList implies prop1_LengthIsSame because if the lists sort to the same list then it must mean that the lengths of the lists were the same.

    2)prop1_LengthIsSame is neither stronger nor weaker to prop3_AllIndicesDifferentValues 
    Explanation
    prop1_LengthIsSame does not imply prop3_AllIndicesDifferentValues because because lists of equal length can have same elements at each corresponding indexes example duplicate lists like [1,2,3] and [1,2,3]
    prop3_AllIndicesDifferentValues does not imply prop1_LengthIsSame because lists can differ at each position and also be of unequal lengths like [1,2,3] [4,5]

    3)prop2_SortsToSameList is neither stronger nor weaker to prop3_AllIndicesDifferentValues
    Explanation
    prop2_SortsToSameList does not imply prop3_AllIndicesDifferentValues because counterexamples like [1,2,3] and [1,3,2] will satisfy prop2_SortsToSameList but not prop3_AllIndicesDifferentValues
    prop3_AllIndicesDifferentValues does not imply prop2_SortsToSameList because counterexamples like [1,2,3] [4,5,6] satisfy prop3_AllIndicesDifferentValues but not prop2_SortsToSameList

    prop2_SortsToSameList implies prop1_LengthIsSame was tested with Haskell - result True as expected
    prop3_AllIndicesDifferentValues implies prop2_SortsToSameList was tested with Haskell - result False as expected
    prop3_AllIndicesDifferentValues implies prop1_LengthIsSame was tested with Haskell - result False as expected

    The folllowing properties test different basic laws for derangements and cannot be compared to each other as neither is naturally a strengthening or weakening of the other.

    4) prop_isDerangementSymmetric: It does not say anything about any other property by itself 

    5) prop_nonEmptyListCannotBeDerangementOfItself: It does not say anything about any other property by itself

    6) prop_reversesPreserveDerangement: It does not say anything about any other property by itself
    

Conclusion

    The implementation works as expected for all the tested scenarios in the domain. 
    The simple scenarios like empty lists, lists of unequal length and permutation but not deragements work as expected
    The implementation identifies which lists are valid derangements.
    The more complex scenarios like lists with duplicate elements which are not deragements and lists wth duplicates which are still valid derangements also works as expected.
