1. Design Report

1.1 Implementation counterexamples

I made the oneTuple function extra to reduce the complexity of the counterexaples function in one line.
The general idea is the following: We get tuples starting from 1 with the k variable. The k variable increase by one in each iteration, because it gets the value from the infinite list [1..].
In each iteration, we get the second element of the tuple with snd and check if that element is not prime. As we want the counterexamples, only if it is not prime, we want to include it in our return list.

1.2 Properties

1.2.1 genRandomCounterTuple and prop_SndIsNotPrime
genRandomCounterTuple gives back a generator which returns randomly an element from the list of the 12 counterexamples. This limit is hardcoded, because of observation results, as later shown in the test report.

In the prop_SndIsNotPrime I check if from the tuple I got back from the generator, the second element is in fact not a prime. For demonstration purposes, I still used a generator here. If we would run quickCheck prop_SndIsNotPrime, it runs 100 tests and for each test, it will randomly select one element from the 12 counterexamples.

1.2.2 prop_SndIsNotPrimeWithoutGen

This is not good, because with the finite small number 12, we can also run test all the counterexamples. That is why I added an Int as input parameter and created an additional property with the same test purpose.
This way, all the 12 counterexamples are tested.

1.2.3 prop_FstIsPrimeWithoutGen

At prop_FstIsPrime I check if all the numbers in the left part of the tuple are prime numbers. Again without generator to test all 12 counterexamples.

1.2.4 prop_FstOrderPrimeWithoutGen
prop_FstOrderPrimeWithoutGen checks if the primes from the tuples are the first prime numbers an no one is skipped.

1.2.5 prop_SecondCalcFirstWithoutGen
This property checks that the second value of the tuple is in fact calculated from the product of the prime numbers of the list + 1.
